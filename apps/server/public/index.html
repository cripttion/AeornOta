Features

Everything you need to ship safely, nothing you don't

A small server on your Cloudflare account, a dashboard, and a command-line tool for macOS and Windows.

Signed end to end

Updates are signed with a key that never leaves your computer or CI. Phones reject anything else, even from a compromised server.

Four-eyes approvals

New code waits for a second person. A leaked CI secret or laptop token can't ship anything on its own.

Gradual rollouts

Start with 10% of phones, watch the error rate, then go to 100%. Every phone keeps its place as you go higher.

Instant undo

Halt a rollout, send phones back to the store build's code, or roll back a Flutter patch, in one click.

Tiny downloads

Phones download only the bytes that changed. Unchanged images and fonts are never downloaded twice.

Fast everywhere

Update checks are answered by the Cloudflare location nearest each phone, from an edge cache.

GitHub Actions, no stored tokens

Workflows prove which repository and branch they run from, and get a one-hour token. The commit shows on the approval.

A dashboard anyone can use

Plain-language pages, help on every screen, an audit log, and guides with macOS and Windows commands.

How it works

From your code to users' phones in four steps

Aeron replaces only the update server. Your apps keep using the official libraries.

  1. 1

    Publish

    Run one command, or let GitHub Actions do it. The update is built and signed with your private key.

  2. 2

    Approve

    A second person checks the message, commit and size in the dashboard, and approves it.

  3. 3

    Roll out

    Phones in the chosen share download it in the background, verify the signature, and switch on the next launch.

  4. 4

    Watch

    See downloads and the error rate per update. Raise the share, or halt and undo in one click.

# once, in your app folder: keys, app.json and native settings
aeron expo init --app calmi --write

# every change: build, sign, upload only what changed
aeron expo publish --app calmi --key keys/private-key.pem --message "Fix paywall copy"
# once, in your Flutter project: keys, shorebird.yaml, permissions
aeron flutter init --app fitloop --write
aeron flutter release --app fitloop          # the store build

# every change: a small signed patch of your Dart code
aeron flutter patch --app fitloop --message "Fix results screen"

Security

Built so nobody else can push code to your users

Independent layers. An attacker has to beat all of them, not just one.

  • Signed on your side. The server never holds a private key.
  • Second-person approval for every new update and patch.
  • Unsigned builds get nothing. Locked keys can't be swapped.
  • No stored CI tokens, thanks to GitHub OIDC.
  • Optional SSO + MFA for approvals with Cloudflare Access.
  • Audit log of every change, with optional Slack or Discord alerts.

What would an attacker need?

Control of your server, database or storage
Not enough. They can't sign updates.
A stolen publishing token or CI secret
Not enough. The upload waits for approval.
Your private key alone
Not enough. They still need a token and an approval.
A phone on hostile Wi-Fi
Not enough. TLS plus end-to-end signatures.

FAQ

Questions people ask

More in the full FAQ.

Do I need to pay Expo or Shorebird?

No. Your apps use the free expo-updates library and Shorebird's open-source Flutter engine. Aeron replaces their servers, so there's no update plan to buy and no Shorebird account needed.

Do the App Store and Play Store allow this?

Both allow apps to download updated JavaScript or interpreted code, as long as an update doesn't change the app's main purpose or get around store policies. Use it for fixes and UI changes, and ship big new features through the stores.

What if an update breaks something?

Start every rollout small. If the error rate jumps, Halt stops it spreading, and Undo or Roll back takes it back from phones that have it. The client libraries also refuse to keep running code that fails to start.

What if the server is down?

Apps keep working with the code they already have. They simply don't get new updates until the server is back.

Mac or Windows?

Both. Every aeron command is the same, and the docs show install steps for each. iOS builds still need a Mac, as always.
